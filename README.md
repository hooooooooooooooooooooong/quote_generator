# 🔮 AI 사주 리포트

생년월일시를 입력하면 **실제 사주 계산 엔진**이 사주팔자·오행·십성·대운을 계산하고, 그 계산 결과를 근거로 **AI(OpenAI GPT)** 가 오늘의 운세·성격·궁합을 글로 풀어주는 웹 앱입니다.

> "AI가 그냥 아무 말이나 지어내는 게 아니라, 실제로 계산된 사주 데이터를 근거로 설명한다"는 점이 이 프로젝트의 핵심입니다.

---

## 1. 왜 만들었나

시작은 "오늘의 명언"을 랜덤으로 보여주는 단순한 앱이었습니다. 
발전 과정:
| 1단계 | 고정 문구 10개 중 랜덤 출력 |→ "이건 아니다" 싶어서 전부 삭제
| 2단계 | AI가 매번 새 문구를 생성 |OpenAI API로 교체해서 AI가 매번 새로 생성
| 3단계 | lunar-python(생년월일을 실제 사주팔자로 변환해주는 계산 라이브러리)으로 **실제 사주 계산** 결과를 근거로 AI가 작성 (지금 방식) |
더 정교한 계산(십성/신살 등)을 위해 "만세력 API" 무료 키를 발급받아 시도→ 
무료 티어가 고정 샘플 5개 생년월일에만 응답하고 실제 사용자가 입력하는 임의의 생년월일은 다 거부하는 걸 발견→ 
lunar-python이라는 무료 오픈소스 파이썬 라이브러리를 써서 직접 계산

할 수 있는 것들:
1. 양력 ↔ 음력 날짜 변환
2. 생년월일시를 입력하면 사주팔자(육십갑자: 년주·월주·일주·시주) 계산
3. 오행, 십성, 12운성, 대운, 공망 같은 명리학 개념까지 계산
실제로 SAZU라는 유료 만세력 API의 계산 결과와 대조해봤는데 100% 일치할 정도로 정확
인터넷 연결 없이 로컬에서 계산 가능 — API 호출 비용도 없고 빠름
| 4단계 | 오늘의 운세 → 사주 리포트 + 오늘의 운세 + 올해의 운세 + 궁합으로 확장 |

## 2. 주요 기능

### 🔮 내 사주 리포트
생년월일시(양력/음력), 성별을 입력하면:

- **사주팔자** — 년주·월주·일주·시주를 한글+한자로 표시
- **십성(十星)** — 각 천간·지지가 일간(본인) 기준 어떤 관계인지 (비견/겁재/식신/상관/편재/정재/편관/정관/편인/정인)
- **12운성** — 장생~양, 각 기둥이 어떤 생애 주기 단계인지
- **공망(空亡)** — 기운이 비어있다고 보는 자리
- **지지 관계** — 육합·삼합·반합·방합·충·형·파·해를 실제 계산해서 표시
- **신살(神殺)** — 역마살(이동/변화), 도화살(매력/인기), 화개살(예술·종교 감수성), 천을귀인(귀인의 도움)
- **신강/신약 판정 + 용신(간이 추정)** — 오행 균형 기준
- **대운(10년 주기)** — 성별에 따른 순행/역행까지 반영해 나이별 흐름을 계산하고, 구간마다 AI 해설을 붙임
- **오행 분포 레이더 차트** (SVG)
- **AI 생성 콘텐츠**: 성격/기질, 오늘의 총운·연애운·재물운, 올해(세운)의 운세, 오행 밸런스 조언

### 💑 궁합 보기
두 사람의 생년월일시, 성별을 입력하면:

- 두 일간의 오행 상생상극 관계(상생/상극/비화)와 오행 보완 정도를 근거로 **궁합 점수(0~100점)** 산출
- 서로의 일간이 상대에게 어떤 십성으로 작용하는지, 일지(배우자궁)·년지 관계까지 계산
- 이 실제 계산값을 근거로 AI가 궁합 총평·잘 맞는 점·주의할 점을 작성

## 3. 기술 스택

| 영역 | 사용 기술 |

| 백엔드 | Python, Flask(인터넷 주소와 파이썬 함수를 연결해주는" 도구 @app.route)
1. 브라우저에서 127.0.0.1:5000 접속할 때
2. "내 사주로 오늘의 운세 보기" 버튼 클릭할 때
3. "두 사람 궁합 보기" 버튼 클릭할 때|	
| 사주 계산 | [`lunar-python`](https://pypi.org/project/lunar-python/) |
| AI 텍스트 생성 | OpenAI API (`gpt-4o-mini`, JSON mode) |
| 프론트엔드 | 순수 HTML/CSS/JavaScript (프레임워크 없음), SVG로 레이더 차트 직접 구현 > 다 기본적인걸로 만듦|
| 환경 설정 | `python-dotenv` > (`.env`에 API 키 저장) 불러오는 라이브러리|

## 4. 작동 구조 (아키텍처)

```
[브라우저]
   │  생년월일시 입력
   ▼
[Flask 서버] ── compute_saju() ──▶ lunar-python으로 실제 사주 계산
   │                                (년주/월주/일주/시주, 오행, 십성,
   │                                 12운성, 공망, 합충형파해, 신살, 대운)
   │
   ├── compute_year_relation() ──▶ 올해 세운 계산
   ├── get_today_ilju()        ──▶ 오늘 날짜의 실제 일진 계산
   │
   ▼
generate_fortunes() / generate_yearly_fortune() / generate_daeyun_readings()
   │  (계산된 실제 데이터를 프롬프트에 근거로 담아 OpenAI에 요청)
   ▼
[OpenAI API] ── JSON 형식으로 해석 텍스트 반환
   ▼
[캐시] 같은 사람 + 같은 날짜 요청은 서버 메모리에 캐싱
   ▼
[브라우저] 결과 렌더링
```

핵심 설계 원칙: **"계산이 필요한 부분(사실)은 코드가 계산하고, AI는 그 계산 결과를 사람이 읽기 좋은 글로 바꾸는 역할만 한다."** 이렇게 역할을 나눈 이유는 아래 5번 항목에서 자세히 설명합니다.

### 어디까지가 "계산"이고 어디부터가 "AI"인가

주요 기능 항목들이 실제로 코드 어디에서 계산되는지 정리하면 다음과 같습니다. `lunar-python`(계산 라이브러리) 기반 항목은 **인터넷 연결 없이도 100% 결정론적으로 계산**되며, OpenAI API는 전혀 관여하지 않습니다.

| 기능 | 코드 위치 | 계산 방식 |
|---|---|---|
`lunar-python` 계산
| 사주팔자 | `compute_saju()`의 `pillars` | `bazi.getYear()` 등 — `lunar-python` 계산 |
| 십성 | `compute_saju()`의 `ten_gods` | `bazi.getYearShiShenGan()` 등 — `lunar-python` 계산 |
| 12운성 | `compute_saju()`의 `twelve_stages` | `bazi.getYearDiShi()` 등 — `lunar-python` 계산 |
| 공망 | `compute_saju()`의 `void_pillars` | `bazi.getDayXunKong()` — `lunar-python` 계산 |
| 대운 | `compute_saju()`의 `da_yun` | `bazi.getYun()` — `lunar-python` 계산 |

밑에꺼는  "달력 계산" 기반인 lunar-python이 못해줌
그래서 밑에 이 세 개는 명리학 교과서에 나오는 정식 조견표를 직접 코드에 옮겨 적어서 판정하는 함수를 사용했고,  이미 SAZU라는 유료 서비스 결과랑 대조해서 검증도 끝냄.
| 지지 관계(합충형파해) | `analyze_zhi_relations()` | 직접 구현한 순수 파이썬 함수 (육합·충·파·해 조견표를 코드에 정의해 판정) |
| 신살 | `compute_sinsal()` | 직접 구현한 함수 (역마·도화·화개·천을귀인 조견표) |
| 신강/신약 | `estimate_strength()` | 직접 구현한 함수 (오행 비율 계산) |

위에서 계산된 값을 프롬프트에 근거로 담아 **OpenAI API 호출**
| 성격/오늘·올해 운세/대운 해설/궁합 총평 등 **문장** | `generate_fortunes()`, `generate_yearly_fortune()`, `generate_daeyun_readings()`, `generate_compatibility_reading()`  |

즉 "사주가 무엇인지"는 계산기처럼 결정론적으로 나오고, "그게 무슨 의미인지"만 AI가 문장으로 풀어씁니다.

## 5. 개발하면서 겪은 문제와 해결 과정

### 문제 1 — "오늘의 운세"인데 새로고침할 때마다 딴소리
- **증상**: 같은 사람이 같은 날 새로고침해도 매번 다른 내용이 나옴
- **원인**: 프롬프트에 실제 "오늘 날짜"가 안 들어가 있었음. AI가 그냥 즉석에서 지어냈을 뿐
- **해결**: 오늘 날짜의 실제 일진(干支)을 계산해서 근거로 명시 + 같은 사람·같은 날짜는 서버에 캐싱 (날짜 바뀌면 자동 갱신)

### 문제 2 — 유료 만세력 API(SAZU)의 함정
- **증상**: 더 정교한 계산을 위해 외부 API 연동 검토
- **원인**: 키를 발급받아 직접 호출해보니, 무료 티어는 **샌드박스**라서 문서에 박힌 5개 고정 샘플 생년월일에만 응답하고 실제 사용자 입력은 전부 거부
- **해결**: 유료 결제 없이는 실사용 불가 → 이미 구현한 자체 계산(`lunar-python`)이 SAZU 유료 샘플 응답과 100% 일치하는 걸 검증하고, 외부 API 없이 직접 구현하는 쪽으로 결정

### 문제 3 — 궁합 점수가 매번 44점만 나온다는 버그 리포트
- **증상**: 사용자 제보 "궁합 점수가 항상 44점만 나온다"
- **원인 조사**: 서버에 임시 로그를 남겨 프론트엔드가 실제로 보낸 값을 추적
- **결론**: 버그 아님. 두 사람의 일간이 **목극토(상극)** 관계였고, 상극은 기본 점수가 낮게 설계되어 있어서 나온 정상 값
- **검증 방법**: 일간 → 관계 판정 → 오행 보정 → 최종 점수, 계산 단계를 하나씩 분해해서 확인

### 문제 4 — AI가 같은 사람을 두고 판정을 다르게 말함
- **증상**: 같은 사주인데 "성격"에서는 "신약", "총운"에서는 "중화"라고 서로 다르게 말함
- **1차 시도**: 프롬프트에 "판정을 모든 항목에서 동일하게 쓰라"고 지시 → 완전히 막지는 못함
- **최종 해결**: 응답을 받은 뒤 정규식으로 잘못된 표현을 실제 계산값으로 교정하는 후처리 로직 추가

## 6. 한계 및 앞으로의 계획

- **격국(格局)·정밀 용신 판별 미구현**: 유파마다 기준이 갈리고 예외 규칙이 많아, 확신 없이 구현하면 틀린 정보를 자신 있게 보여주는 위험이 있어 의도적으로 제외했습니다. 대신 "간단 추정"이라고 명시한 신강/신약 기반 용신만 제공합니다.
- **배포되지 않음**: 현재는 로컬 환경(Flask 개발 서버)에서만 동작합니다. 공개 배포 시에는 API 호출 비용을 통제할 요청 제한(rate limit) 장치가 필요합니다.



## 7. 실행 방법

```bash
# 1. 의존성 설치
pip install -r requirements.txt

# 2. .env 파일 생성 후 OpenAI API 키 입력
cp .env.example .env
# .env 파일을 열어 OPENAI_API_KEY=sk-... 입력

# 3. 서버 실행
python app.py

# 4. 브라우저에서 접속
# http://127.0.0.1:5000
```
